archiveview

Config files and the view format

archiveview keeps its files in $XDG_CONFIG_HOME/archiveview when XDG_CONFIG_HOME is set, otherwise ~/.config/archiveview:

~/.config/archiveview/
├── settings.json
├── history.json
└── views/
    ├── default.json
    └── beam.json

All are pretty-printed JSON, written atomically (to a hidden temporary file, then renamed), so a crash never leaves half a file. Missing fields take their defaults, so files can be edited by hand; fields archiveview doesn't know are kept when it saves settings.json. A settings.json that is not valid JSON gives the defaults for that run, with a warning, and is not saved over until it is fixed.

settings.json

{
  "archiver_url": "http://archiver.example.org:17668/retrieval",
  "recent_archivers": [
    "http://archiver.example.org:17668/retrieval",
    "http://127.0.0.1:17668/retrieval"
  ],
  "theme": "system",
  "save_default_on_exit": true
}
fielddefaultmeaning
archiver_urlnonethe archiver used when neither --archiver nor the view opened at start-up names one. Written by --archiver, and by switching to another archiver in the pill or by opening a view (not by No archiver).
recent_archiversnonearchivers used recently, newest first (at most 8), offered by the archiver pill
theme"system""system" (follow the OS), "light" or "dark"; set from the ≡ menu
save_default_on_exittruesave the plot as the default view on quit, so the next start (with no PVs or --view) reopens where you left off

A missing or unreadable settings.json gives the defaults (an unreadable one logs a warning).

history.json

The search box's recent searches, newest first, saved each time they change:

{
  "searches": [
    { "text": "BL16I-EA-*" },
    { "text": "SR01C-DI-EBPM-01:SA:.*", "regex": true }
  ]
}
fieldmeaning
searches[].textthe text as typed
searches[].regextrue when the .* toggle was on; default false

At most 50 are kept. A missing or unreadable file means no recent searches (an unreadable one logs a warning, and is replaced the next time a search is remembered). Delete it, or use Clear search history in the ≡ menu, to forget them.

views/NAME.json

{
  "version": 1,
  "pvs": [
    { "name": "SR-DI-DCCT-01:SIGNAL" },
    { "name": "pva://bl01t:SUM", "color": "#d62728", "visible": false }
  ],
  "range": { "kind": "relative", "secs": 28800 },
  "y": { "autoscale": true },
  "archiver": "http://archiver.example.org:17668/retrieval"
}
fieldmeaning
versionthe format version, 1. A file with a newer version than the program knows is refused.
pvsthe traces, in chip order
pvs[].namethe PV as typed: NAME, ca://NAME, pva://NAME, sim://sine, ...
pvs[].color#rrggbb; when absent, the palette colour for its position
pvs[].visiblefalse for a hidden trace; default true
range{"kind": "relative", "secs": S}: the last S seconds, following now; or {"kind": "absolute", "start": "...", "end": "..."} with RFC 3339 UTC times such as "2026-10-17T09:00:00Z"
y.autoscaledefault true
y.min, y.maxthe value range when autoscale is false
archiverthe retrieval URL in use when the view was saved; opening the view switches to it. Optional: older files lack it, and the format version is still 1.
y.logtrue for a log value axis; default false

View names can't be empty, start with ., or contain / or \. The view called default opens at startup when no PVs and no --view are given.

A host app that embeds the plot gets the same structure from Plot::view() and can store it in its own files; see Embed the plot.
