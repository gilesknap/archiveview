Plot: the embeddable archived + live time-series widget.

See DESIGN.md (“Embedding”, “Data flow” and “UI”) for the interaction model, fetch policy and live merge. The pieces:

  • series: a trace’s live samples, archived history, and their merge;
  • fetch: background archive requests on the pv crate’s runtime;
  • window: time window and value range maths (pan, zoom, presets);
  • timeaxis: ticks and adaptive labels in local time;
  • render: painting the plot area;
  • bar: the slim top bar (search, range pill, live pill, archiver pill, buttons);
  • legend: the chips under the plot;
  • hover: the crosshair readout, empty state and status line;
  • axes: which value axis a trace joins, and the axes’ names;
  • status: whether the archiver can be reached;
  • paste: adding PVs from the primary selection or the clipboard.

pv_names
The PV names in text, in order and once each. It is split into words on whitespace, commas and semicolons, and quotes and brackets around a word are dropped. A word can be a name if, after an optional ca:// or pva://, it has only characters EPICS record names use (letters, digits, _ - + : [ ] < > { } $, and . before a field), at least one letter, and does not start with - or + (a command-line flag) or start or end with . or :. Unless it has a scheme, shapes that are something else are left out: times and dates (12:30:00, 2026-10-17T13:41:52Z), host:port (two parts, a host name with a ., localhost or lower case, then digits: not SR:BPM:01 or DLS:01), a::b paths, and in running text Python log lines (INFO:root:Connected; WARN:LIMIT is a name).
