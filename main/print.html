archiveview

archiveview

archiveview plots EPICS PVs against time. History comes from an EPICS Archiver Appliance and live values come from Channel Access or PV Access, joined into one line per PV. It is written in Rust with egui, in the style of bobview.

It covers what most people use the Phoebus Data Browser for, with a much smaller interface. The plot fills the window, a slim bar holds search and the time range, and everything else is direct manipulation: drag to pan, scroll to zoom, hover to read values. See Scope, and how it differs from the Data Browser.

Quick start

This tutorial installs archiveview and plots archived and live PVs on your own machine. It takes about ten minutes and needs no EPICS installation, no IOCs and no real archiver:

  • archiveview-mockarchiver plays the part of an Archiver Appliance, serving 30 days of synthetic history for a handful of PVs;
  • bobview-testioc (from bobview) serves the BL01T simulated beamline live, including PVs the mock also archives, so you can watch the archive and the live values join up.

You need an x86_64 or aarch64 Linux machine, or a Mac.

1. Install

On Debian or Ubuntu, first install the graphics libraries:

sudo apt install libxkbcommon0 libwayland-client0 libegl1 libgl1-mesa-dri

(on RHEL and Fedora see Install archiveview; macOS needs nothing). Then install archiveview into ~/.local:

curl -sSfL https://raw.githubusercontent.com/gilesknap/archiveview/main/install.sh | bash
archiveview --version

If the command is not found, add export PATH=$HOME/.local/bin:$PATH to your shell's start-up file and open a new terminal.

2. Start the mock archiver

archiveview-mockarchiver &

It listens on http://127.0.0.1:17668, the Archiver Appliance's usual retrieval port. The PVs it serves are listed in Mock archiver.

3. Plot some history

archiveview --archiver http://127.0.0.1:17668 MOCK:SINE MOCK:NOISE

The window opens on the last hour. Each PV is a line in its own colour, and a chip for each sits along the bottom with its latest value.

  • Hover over the plot: a crosshair shows every trace's value and the time under the pointer.
  • Scroll to zoom the time axis about the pointer, and drag to pan. As you zoom out, the archiver sends the data thinned to the plot's width; where a pixel holds many samples you see the line's mean with a shaded min-to-max band.
  • Click 7d in the time-range pill to see the whole week, then double-click the plot to return to where you started.
  • The pill reading ● 127.0.0.1:17668 is the archiver: its dot is green while the archiver answers. Hover over it for details.

archiveview remembers --archiver, so from now on you can leave it out.

4. Find another PV

Press / (or click the search box) and type ramp. The archiver's matching PVs appear as you type; pick MOCK:RAMP with the arrow keys and Enter, or click it.

5. Add live values

Start the simulated beamline, and tell Channel Access to look for PVs on this machine:

bobview-testioc &
export EPICS_CA_ADDR_LIST=127.0.0.1 EPICS_CA_AUTO_ADDR_LIST=NO
archiveview --range 10m bl01t:SUM

(install the IOC first with cargo install bobview-testioc, or take it from a bobview release).

The mock archives bl01t:SUM and the IOC serves it live. The line runs from the archive into the live values at the right edge, and the ● Live pill shows a red dot while the plot follows the current time. Drag the plot to the left: live following stops. Press L, or click the pill, to jump back to now.

6. Save the view

Open the ≡ menu, type demo into the Save as… field under Views and press Enter. Next time, archiveview --view demo reopens the same PVs and time range, from the same archiver. Plain archiveview reopens the plot as you left it. See Save and load views.

7. Finish

Close the window, then stop the background programs:

kill %1 %2

Install archiveview

archiveview runs on x86_64 and aarch64 Linux and on macOS 11 or later (Apple silicon or Intel). install.sh picks the release build to match the machine.

Install the prerequisites

On Debian and Ubuntu:

sudo apt install libxkbcommon0 libwayland-client0 libegl1 libgl1-mesa-dri

On RHEL, Rocky, Alma and Fedora:

sudo dnf install libxkbcommon libwayland-client libglvnd-egl mesa-dri-drivers

None are needed on macOS.

Install the release

curl -sSfL https://raw.githubusercontent.com/gilesknap/archiveview/main/install.sh | bash

This installs into ~/.local (set PREFIX to choose another place):

filewhat
bin/archiveviewthe plotter
bin/archiveview-sshruns the plotter with software OpenGL, for ssh -X; see Run over ssh
bin/archiveview-mockarchivera mock Archiver Appliance with synthetic history; see Mock archiver
share/archiveview/the README, licence and THIRD_PARTY_LICENSES.txt

The Linux binaries are linked against glibc 2.28, so they run on RHEL 8+, Ubuntu 20.04+ and Debian 10+.

Run from inside an unpacked release tarball, install.sh installs that tarball rather than downloading one.

Put it on your PATH

On macOS ~/.local/bin is not on PATH by default; add this to ~/.zshrc:

export PATH=$HOME/.local/bin:$PATH

Upgrade or remove

Run the install command again to upgrade. To remove archiveview, delete the bin/archiveview* files and share/archiveview from ~/.local. Your saved views and settings are in ~/.config/archiveview.

Connect to an archiver and IOCs

archiveview reads history from an Archiver Appliance over HTTP and live values from IOCs over Channel Access or PV Access. Either can be left out: with no archiver it plots live values only, and a PV the archiver does not know about still plots live.

Point it at the archiver

Pass the appliance's retrieval URL, normally port 17668:

archiveview --archiver http://archiver.example.org:17668 SR-DI-DCCT-01:SIGNAL

/retrieval is added for you, so http://host:17668 and http://host:17668/retrieval mean the same. A single-container appliance that serves everything on one port works the same way, e.g. http://host:17665. See The archiver URL and API.

--archiver is remembered: archiveview writes it to settings.json as archiver_url (see Config files), so later runs use it without being told. Give --archiver again only to change archivers, or --no-archiver for a run with live values only.

At start-up the archiver is chosen in this order:

  1. --archiver URL;
  2. none, with --no-archiver;
  3. the archiver the opened view was saved with (the default view restored at start-up, or --view NAME);
  4. archiver_url in settings.json.

See and change the archiver

The pill right of Live in the top bar shows the archiver's host and a dot:

dotmeaning
greenthe archiver answers
amberit does not: no connection, a gateway error, or a URL that is not an archiver
spinnerchecking, at start-up or after a change
hollow grey, "No archiver"none is set: live values only

archiveview asks the appliance for its version (bpl/getVersion) at start-up and after a change. After that every history fetch and search updates the dot: a success turns it green, and a failure that looks like the archiver's is checked with another version request before the dot turns amber (one slow query timing out is not the archiver down). While it is amber the archiver is checked again every minute, so it turns green when the archiver comes back. A PV that is not archived (a 404 for that PV) is not an archiver error.

Hover over the pill for the full retrieval URL, the appliance's version, and the last error and when it happened. Click it to switch archivers without restarting: type a URL and press Enter (or Use), pick one of the recently used archivers, or choose No archiver. Use on the archiver already in use checks it again at once. The plotted PVs' history is fetched again from the new archiver.

A switch to another archiver, in the pill or by opening a view saved with one, is remembered in settings.json like --archiver. No archiver is for this run only: the settings keep the last archiver, so the next run without --archiver uses it again. In a narrow window the pill shrinks to its dot.

Reach the IOCs

Live values use the standard EPICS client environment variables, as any CA or PVA client does:

export EPICS_CA_ADDR_LIST="10.0.0.10" EPICS_CA_AUTO_ADDR_LIST=NO
export EPICS_PVA_ADDR_LIST="10.0.0.10" EPICS_PVA_AUTO_ADDR_LIST=NO

A PV name with no prefix uses Channel Access. Prefix it with pva:// for PV Access, e.g. pva://bl01t:SUM. The other prefixes of bobview's pv crate also work for live values (sim://sine, loc://name), which is handy for trying the plot out; the archiver is asked only about plain names.

archiveview never writes to PVs.

Check what is happening

The plot's chips show a PV's state: a spinner while its history loads, a grey "—" when it is disconnected (hover for the reason), and a "live only" mark when the archiver has no record of it (HTTP 404). A ! on a chip means its last archive request failed; hover the chip for the error. For more detail run with ARCHIVEVIEW_LOG=debug, which logs every archiver request.

Find and add PVs

Search the archiver

Press /, or click the search box at the left of the bar, and type part of a name. After a short pause the box lists the archiver's matching PVs:

  • The first match is highlighted: ↑/↓ move through the list, Enter adds the highlighted row, and a click adds the one clicked.
  • A PV whose name is exactly what you typed is always the first match, so typing a full name and pressing Enter adds that PV, even when other names containing it sort before it.
  • Adding a PV keeps the text and the list, so you can add several from one search: ↓, Enter, ↓, Enter, ... PVs already on the plot are dimmed with a ✓, and picking one again does nothing.
  • Esc closes the list and keeps the text (↓ or a click brings the list back); a second Esc, or the ✕ in the box, clears it. A click elsewhere closes the list and keeps the text.
  • Coming back to the box (a click, or /) selects its text, so typing starts a new search; press → or End to edit the old one instead.
you typearchiver is asked for (regex)matches
dcct(?i).*dcct.*any name containing dcct, in any case (SR-DI-DCCT-01:SIGNAL)
ES{Dif}(?i).*ES\{Dif\}.*as written: {, (, ., + and the like match only themselves
SR-DI-*:SIGNALSR-DI-.*:SIGNALthe whole name, with case; * is any run of characters
BL0?T*BL0.T.*? is any one character

Text without * or ? is searched as a substring, ignoring case. With * or ? it is a glob: it must match the whole name, case and all, and every other character stands for itself.

Click the .* toggle inside the box to type a Java regular expression instead. It must match the whole name: SR-DI matches nothing, while SR-DI.* works. Start it with (?i) to ignore case.

The list shows the first 50 matches; type more of the name to narrow it.

Reuse a recent search

archiveview remembers a search once you add a PV from it (typos and half-typed names are not kept), with its .* setting. It keeps the last 50, in history.json in the config directory, so they survive a restart. Plain text that differs only in case (bl16i, BL16I) is one search, kept as you last typed it.

  • Click the empty box, or press /: the list shows your recent searches under Recent. Pick one with ↓ and Enter, or a click, to put it back in the box and search again. Nothing is added until you pick a match.
  • While typing: recent searches that start with (or contain) the text come first, marked with a clock, above the archiver's matches. Enter still adds the first match; move up to a recent search to use it. So typing BL16I offers BL16I-EA-* from yesterday.
  • Hover a recent search and click its ✕ to forget it, or choose Clear search history in the ≡ menu to forget them all.

Add a PV the archiver doesn't know

Type the full name: as well as any archived matches, the list ends with an Add "…" as typed row. Highlight it with ↓ (or click it) and press Enter. The text is added as written, so this is how to add a PV that is not archived; it plots live only. A PV Access or simulated name (pva://name, sim://sine), or several names separated by spaces or commas, can only be added as typed, so that row comes first and Enter adds it straight away.

Add PVs from the command line

Name them after the options:

archiveview --archiver http://archiver:17668 SR-DI-DCCT-01:SIGNAL SR-DI-DCCT-01:LIFETIME

Globs are not expanded on the command line; each argument is one PV.

Remove or hide a PV

Each PV has a chip along the bottom of the plot. Click a chip to hide its trace (the dot turns hollow) and again to show it. Hover a chip to highlight its trace: it is drawn bolder and on top, with its min/max band, while the others dim. That finds a trace hidden under another with the same values, or under the bands of busy PVs. Click its ✕ to remove it.

With no archiver

Without an archiver, there is nothing to search: the only row is Add "…" as typed, so type full names and press Enter.

Navigate the plot

Everything happens on the plot itself; there are no axis dialogs. The full list is in Gestures and keys.

Choose a time range

The pill in the bar holds the presets 1h, 8h, 1d and 7d. A preset shows that span ending now, following the current time.

The ⋯ segment opens a small popover for anything else: type a span such as 90m, 2 days or 1 hour 30 min, or give a start and an end date-time.

When you have zoomed or panned away from a preset, no segment is lit and the pill shows the span you are looking at, such as 3h 20m.

Pan and zoom time

  • Drag the plot left or right to pan. Let go while moving and it glides to a stop.
  • Scroll, or pinch on a trackpad, to zoom about the pointer.
  • A horizontal trackpad swipe pans.
  • ← and → pan by a tenth of the span; + and - zoom about the middle.

Zoom to a box

Right-drag, or shift-drag, a box over the part you want. Both the time and value axes zoom to it.

Zoom values

Each value axis scales itself to its traces' visible data, including the min/max bands. Traces with different units, or values of very different sizes, get axes of their own; see Work with value axes.

  • Drag up or down on an axis (its labels), or shift- or ctrl-scroll over it, to zoom that axis alone.
  • Shift- or ctrl-scroll over the data zooms every axis about the pointer, and dragging the plot pans the values of any axis that is zoomed.
  • Zooming an axis turns its autoscale off. The ⤢ button, or A, turns it back on for all of them.

Follow now, or look at the past

While the plot follows the current time, the ● Live pill shows a red dot and new values appear at the right edge. Panning or zooming into the past stops following. Click the pill, press L, or drag back to the right edge to follow again.

Read values

Hover over the plot. A vertical hairline follows the pointer, with a card showing the time and each visible trace's value there, with its units, coloured by alarm severity when it is in alarm. Where the archiver has thinned the data into bins, the card also shows the bin's min and max.

Start again

Double-click the plot, press Home, or click ⌂: the time range returns to the last preset and autoscale turns on.

Work with value axes

You never have to set up a value axis: each PV picks one when its data first arrives, and the axes name themselves. When the choice is not the one you want, moving a trace takes a click or two.

How a new PV picks its axis

When a PV's data arrives (its archived history, or a second of live values if it has no history), archiveview compares it with the axes already on the plot. PVs pick in the order of their chips, whatever order the archiver answers in, so a view always comes up the same way; a PV is drawn once it has picked.

  • Units first. A PV never joins an axis whose traces have other units: a beam current in mA and a lifetime in h get an axis each. This holds however many axes there are.
  • Then size. With the same units (or none), it joins an axis whose values are within about a factor of ten of its own, a little more when their ranges overlap. SA:X and SA:Y of a BPM, both in mm, share an axis; a current of 300 mA and one of 0.3 mA do not.
  • States apart. An enum or binary PV gets an axis of its own, named after it, with ticks at whole numbers. Only enums with the same states share one ("State").
  • Log scale. A pressure, or a PV whose values span several decades, gets an axis on a log scale.
  • About four axes. Past four axes of values, a new PV joins the closest axis with its units even when the sizes differ; with none, it still gets its own.

The choice is made once. Zooming, panning and reloading never move a trace to another axis; only you do.

The axes alternate sides: the first on the left, the second on the right, then a third left of the first and a fourth right of the second. The first chip's axis is always the first.

Move a trace to another axis

  • Click the colour dot on its chip for a menu of the axes, and New axis.
  • Or drag the chip onto an axis. Drop it anywhere else on the plot to give it an axis of its own.

An axis that loses its last trace disappears.

Pick out an axis' traces

Click an axis (its labels or name) to show its traces in full and dim the others. Click it again to show them all.

Zoom one axis

With the pointer over an axis, drag up or down or shift-scroll to zoom that axis alone. Over the data, shift-scroll zooms every axis about the pointer. ⤢ or A autoscales them all again.

Names

An axis names itself from its traces:

  1. the quantity from the units, such as Current (mA), Position (mm), Time (h); unknown units show as they are, (counts);
  2. when two axes have the same units, the part of the PV names that tells them apart: Position X (mm) and Position Y (mm);
  3. without units, the PV's description, when the archiver gives one;
  4. otherwise Axis 1, Axis 2, ...

An axis of states is named after its PV, or State when several share it.

Hover a name to read it in full, with its units and its traces. Double-click a name to type your own; Enter keeps it, Esc does not. Clear it to go back to the automatic name.

An axis with one trace shows its name in the trace's colour. One with several shows a small dot in each trace's colour by its name.

Log scale

Right-click an axis for its own menu: Log scale, Autoscale and Rename…. ≡ ▸ Log scale turns the log scale on or off for every axis.

Everything here (which trace is on which axis, each axis' zoom, log scale and name) is saved with the view.

Save and load views

A view is the set of PVs on the plot (with their colours and whether they are shown), the time range and the value-axis settings. Views are saved as small JSON files in ~/.config/archiveview/views/, one per name.

Save a view

Open the ≡ menu at the right of the bar. Under the Views heading:

  • Save NAME saves over the view you opened.
  • The Save as… field: type a name and press Enter (or Save). Names can't be empty, start with ., or contain / or \.
  • Save as default saves to default, which opens when archiveview starts with no PVs and no --view.

A view also records the archiver in use when it was saved.

Open or delete a view

≡ ▸ Open ▸ NAME opens a saved view (the default is listed first). If the view was saved with a different archiver, archiveview switches to it; the archiver pill shows the change. ≡ ▸ Delete ▸ NAME removes one. From the command line:

archiveview --view beam

Keep the default up to date

Save default on exit (under Views in the ≡ menu) is on unless you turn it off: archiveview saves the current plot as default whenever you quit, so starting it with no PVs and no --view reopens it as you left it, with the same archiver. The choice is kept in settings.json.

When the default view is restored, a notice at the bottom says "Restored last session" for a few seconds. Its Start empty button clears the plot instead (keeping the archiver). PVs given on the command line start a new plot of just those PVs rather than adding to the restored one; with Save default on exit on, that plot becomes the default when you quit.

What is restored

savedrestored as
a relative range (e.g. the last 8 hours)that span ending now, following live
an absolute rangeexactly those start and end times
which trace is on which value axisas saved: traces do not pick again
an axis' autoscale, or its min and max, log scale and nameas saved
a trace's colour and hidden stateas saved
the archiverswitched to, unless --archiver or --no-archiver is given

A run with --no-archiver saves the default view on exit with the archiver it had before, so one live-only run doesn't make the next start forget it. A view saved without an archiver (or by an older archiveview) keeps the archiver in use, so the same view works against another appliance; so does a hand-edited view with the archiver field removed.

Views can be edited by hand or shared by copying the file; see Config files and the view format.

Run over ssh

archiveview draws with OpenGL. Two commands start it:

commanddraws withuse it
archiveviewthe machine's own OpenGL: the GPU, or whatever driver the desktop providesnormally: on a local desktop, a laptop, a Mac
archiveview-sshMesa in software, on the CPU of the machine archiveview runs onwhen the OpenGL path can't work, such as over ssh -X

Both take the same arguments. Start with archiveview, and switch to archiveview-ssh if it fails to start or draws nothing.

When to use archiveview-ssh

  • Over ssh -X or -Y. This is what it was named for. Forwarded OpenGL reaches your local X server as indirect GLX, which current X servers refuse, so archiveview exits with glutin error: [2] BadValue.
  • Where a GPU driver is installed but can't be used, for example a remote desktop, VNC or Xvfb session on a machine with an NVIDIA driver: glvnd picks NVIDIA's GL, which then has no GPU display to draw on.
  • Where the GPU driver is broken or misbehaves, as a workaround while you sort it out.

There is no need for it on macOS or on Wayland or X11 desktops with working graphics. --snapshot needs neither: it draws without OpenGL or a display.

What it does

archiveview-ssh is a small script that runs archiveview with:

  • LIBGL_ALWAYS_SOFTWARE=1, so Mesa renders on the CPU (llvmpipe);
  • __GLX_VENDOR_LIBRARY_NAME=mesa, and __EGL_VENDOR_LIBRARY_FILENAMES pointing at Mesa's EGL vendor file, so libglvnd picks Mesa rather than a GPU vendor's library such as NVIDIA's.

Over X forwarding the finished window then travels to your X server as plain images, which every X server accepts.

Software rendering costs CPU on the machine running archiveview, and over ssh -X each redraw sends the whole window over the network. archiveview redraws only for your input, when new data arrives, and, while following now, at the pace the time axis scrolls, so this is usually quick enough.

Requirement

Mesa must be installed where archiveview runs: mesa-dri-drivers on RHEL, libgl1-mesa-dri on Debian and Ubuntu (both are in the install prerequisites).

Example

ssh -X control-host
archiveview-ssh --archiver http://archiver:17668 SR-DI-DCCT-01:SIGNAL

Take snapshots

--snapshot renders the plot to a PNG without opening a window, then exits. It needs no display and no GPU, so it works in CI, over ssh and in containers. Use it for documentation, regression checks, and reports.

archiveview --archiver http://archiver:17668 --snapshot beam.png --range 7d SR-DI-DCCT-01:SIGNAL

Everything else on the command line applies as usual: the PVs, --view, --range and the archiver.

Size, scale and theme

archiveview --snapshot out.png --size 1920x1080 ...
archiveview --snapshot out.png --scale-factor 2 ...      # as on a high-DPI screen
archiveview --snapshot out.png --theme dark ...

--size is in pixels and defaults to 1280x800. Snapshots use the light theme unless --theme dark is given.

Wait for data

The snapshot is taken after --wait seconds (default 2), and not before every archive request has finished, so history is always drawn. It gives up waiting after 60 seconds. Raise --wait to give live PVs time to connect and gather a few values:

archiveview --snapshot out.png --wait 5 --range 10m bl01t:SUM

What CI does

CI starts the mock archiver and bobview-testioc, then snapshots a set of views and uploads them as the snapshots artifact of each run:

archiveview-mockarchiver --port 17668 &
bobview-testioc &
export EPICS_CA_ADDR_LIST=127.0.0.1 EPICS_CA_AUTO_ADDR_LIST=NO
archiveview --archiver http://127.0.0.1:17668 --snapshot snapshots/mock-1h.png \
    --size 1280x800 --wait 5 --range 1h MOCK:SINE MOCK:NOISE MOCK:NAN
archiveview --archiver http://127.0.0.1:17668 --snapshot snapshots/empty.png --size 1280x800
kill %1 %2

The set covers the empty state, a short and a long range (raw steps and min/max bands), the dark theme, a live trace joining its history, a narrow window and a plot with no archiver. See .github/workflows/ci.yml for the full list. Look at them, rather than only checking they were written: the plot should fill the window, bands should shade binned data, the time labels should read well and the chips should be tidy.

Embed the plot in an egui app

The plot is a library widget, archiveview::Plot, and the archiveview program is a thin window around it. Any egui 0.36 app can show one, and as many as it likes; bobview is meant to use it for its trend windows.

[dependencies]
# default-features = false: just the widget, without the standalone app's
# eframe, png and clap
archiveview = { git = "https://github.com/gilesknap/archiveview", default-features = false }
pv = { package = "bobview-pv", version = "1.8" }
egui = "0.36.2"

The host must use the same pv crate as archiveview, the bobview-pv package: Cargo treats two packages with different names as different crates, even from the same source, so a PvManager from a path dependency on a package called pv cannot be passed to Plot::new. bobview itself therefore names its in-tree crate's package bobview-pv (keeping pv as the name it is imported by) and points the published one at it:

# bobview's workspace Cargo.toml
[patch.crates-io]
bobview-pv = { path = "crates/pv" }

#![allow(unused)]
fn main() {
use archiveview::{ArchiverClient, Plot};

// once, in the app's constructor; share the app's own PvManager
let pvs = pv::PvManager::new();
let archiver = ArchiverClient::new("http://archiver:17668").ok();
let mut plot = Plot::new(&pvs, archiver);
plot.add_pvs(&["SR-DI-DCCT-01:SIGNAL".to_string()]);

// each frame, e.g. inside an egui::Window: give it a size, as the plot
// fills whatever space it is offered (at least 360 x 200)
egui::Window::new(plot.title())
    .id(egui::Id::new("trend-1"))
    .default_size([720.0, 420.0])
    .resizable(true)
    .show(ctx, |ui| plot.ui(ui));
}

What the widget does, and doesn't, assume:

  • It uses the host's PV context. Plot::new takes the host's pv::PvManager, subscribes through it, and runs archive requests on that manager's tokio runtime. It starts no runtime or threads of its own.
  • No archiver is fine. With None it plots live values only, like bobview's trend window. set_archiver changes it later.
  • The archiver is the host's unless it says otherwise. The archiver pill always shows whether the archiver can be reached (plot.archiver_status()), but by default it is a status display only, and set_view ignores a view's archiver, so a layout restored later never moves the plot to another archiver. plot.set_archiver_switching(true) (as the standalone app does) lets the user switch archivers in the pill and makes set_view follow a view's archiver. The plot then switches itself, and plot.take_archiver_change() is true once afterwards so the host can remember the choice; give it the host's remembered archivers with plot.set_recent_archivers(..). Persisting them is the host's job: the widget writes no files.
  • No globals. Every plot keeps its own state and egui ids, so several can be open at once. Plot::new salts its ids with a running count; Plot::with_id_salt(&pvs, archiver, "trend-1") uses the host's own salt, which keeps them stable when the host rebuilds its plots.
  • The host owns the look. The plot follows ui.visuals() (light or dark) and the host's fonts; it never sets the theme or installs fonts.
  • It repaints itself when archive data arrives (in the viewport it was last drawn in, so a plot in its own native window is repainted, not the root one) and, while following now, at the pace the time axis scrolls.

To save a plot in the host's own layout files, store plot.view() (it is serde-serialisable) and restore it with plot.set_view(&view). A view records the archiver in use; set_view switches to it only with archiver switching on. plot.is_loading() is true while archive requests are in flight.

The search box remembers recent searches in memory only. To keep them across runs, as the standalone app does in history.json, give the plot the saved list with plot.set_search_history(history) and save plot.search_history() (a serde-serialisable SearchHistory) whenever plot.search_history_changed() returns true. A host with several plots can share one list by passing it between them the same way.

See the Rust API for the full interface.

Scope, and how it differs from the Data Browser

What archiveview is for

Looking at how PVs have behaved: what the beam current did overnight, when a vacuum gauge started to climb, whether a motor's readback settled. You name some PVs, choose a time range, and read the plot. For that it needs:

  • history from an EPICS Archiver Appliance, and live values from Channel Access or PV Access, as one line per PV;
  • several PVs on one shared time axis;
  • fast pan and zoom from a week down to seconds;
  • reading exact values and times off the plot;
  • saving a set of PVs and a range to come back to.

What it leaves out

The Phoebus Data Browser does a great deal more, and exposes it through property sheets, trace tables, axis configuration dialogs, archive data source lists and long context menus. archiveview has none of these. In v1 it also leaves out:

  • axis dialogs: value axes are chosen automatically, and moved from a chip's dot or by dragging the chip;
  • exporting data (CSV, spreadsheet);
  • statistics, formulas and waveform views;
  • .plt files;
  • more than one archiver at a time.

Some of these may come later, but only where they can be done without bringing back the configuration panels.

How it feels instead

archiveview takes its cues from modern charting tools such as Grafana, TradingView and Apple Stocks:

  • The plot is the interface. It fills the window; a slim bar holds search, the time-range pill, the live toggle and two buttons.
  • Direct manipulation replaces settings. Drag to pan, scroll or pinch to zoom, drag a box, drag the value axis; double-click to go back.
  • Read by hovering. A crosshair card shows every trace's value, units and severity at the pointer's time.
  • Traces are chips, not table rows: click to hide, hover to highlight, ✕ to remove.
  • Sensible defaults stand in for options: autoscale over what is visible, colours from a palette that works on light and dark backgrounds, min/max bands wherever the archiver has thinned the data, and time labels that adapt from 14:30 to Tue 17 to Oct.

Relationship to bobview

archiveview shares bobview's look, fonts, palette and PV library, and its plot widget is meant to replace bobview's own trend window, so a trend opened from a bobview display gains history from the archiver.

Fetching history

When the time range changes (a preset, a pan, a zoom, or the live view scrolling on), the plot waits 300 ms for things to settle, then asks the archiver for each PV's history over the visible range plus a quarter of the span either side, so small pans show data straight away. Each trace has at most one request in flight; a newer one makes older answers stale, and they are dropped when they arrive. The old history stays on screen until the new one lands, so nothing flickers.

For scalar numeric PVs the request is wrapped in the appliance's optimized_N operator, with N twice the plot's width in device pixels (at most 4000). The appliance then decides:

  • if the range holds no more than N samples, it returns them raw, drawn as steps (each value holds until the next sample, which is what an archived sample means);
  • otherwise it returns N bins, each with the mean, min, max and count, drawn as the mean line over a translucent min..max band.

So the amount of data sent is bounded by the plot's width, not the time range: a week of a 10 Hz PV costs the same as an hour.

Strings and enums are fetched raw (an enum's index). The plot asks the archiver's getMetadata once per PV to learn its type, and falls back to the shape of the first response.

Array (waveform) PVs are not plotted: a line of one element over time says little about a waveform, so their chip shows the latest array instead. When the metadata says a PV is an array, no data is fetched at all; without metadata, the first response tells, and its samples are dropped.

Joining live values

Each trace subscribes to its PV through the pv crate and records every update into a ring buffer, stamped with the IOC's timestamp, the same clock the archiver stored, so the two line up. History is cut at the first live sample, so at the right edge the live values always win, and since both are drawn as steps the join is seamless. A disconnect records a gap.

While the plot follows now, the history behind the live values is topped up: raw history every 30 seconds or so, by fetching only what is new since its last sample; binned history by fetching the (bounded) window again, but only once time has moved on by a few bins, so a week-long view asks the archiver for its week of bins every half hour, not every 30 seconds. Each trace has at most one request to the archiver at a time.

Drawing

Each frame, the visible part of every trace is thinned to at most four points per pixel column (first, min, max, last), which keeps every peak while drawing a bounded number of segments. Gaps (NaN values, and the archiver's disconnection markers) break the line. Autoscale covers the visible values including the bands, and the value axes animate to their new ranges. A trace picks a value axis once, when its first data arrives: by units, then by the size of its values, so a current in mA and a lifetime in hours are both readable while the two planes of a BPM share one axis. The rules are pure functions over a trace's value statistics (plot/axes.rs), tested as a table.

The widget and the app

archiveview::Plot holds everything about one plot and nothing global, so several can share one window or one program, and it borrows the host's PV manager and runtime. ArchiveApp wraps one plot with the window chrome: fonts, theme, the ≡ menu, and loading and saving views and settings in ~/.config/archiveview. main.rs adds the command line and either opens a window or renders a snapshot.

The archiver URL and API

archiveview talks to the EPICS Archiver Appliance over its HTTP retrieval API. It needs only read access to retrieval; nothing on the management interface.

The URL

Give the retrieval base, as for any retrieval client:

--archiverbecomes
http://host:17668http://host:17668/retrieval
http://host:17668/http://host:17668/retrieval
http://host:17668/retrievalunchanged
https://archiver.example.org/retrievalunchanged (behind a proxy)

An appliance installed as separate Tomcats serves retrieval on port 17668 (17665 is management). The single-container quick-start appliance serves everything on 17665.

Requests

With R the retrieval base:

purposerequest
historyR/data/getData.json?pv=OP(PV)&from=T&to=T
searchR/bpl/getMatchingPVs?pv=GLOB&limit=50, or regex=RE
PV typeR/bpl/getMetadata?pv=PV, once per PV
is it there?R/bpl/getVersion, at start-up and after a change of archiver, then every minute while it fails

Times are sent in UTC as 2026-10-17T09:00:00.000Z. OP is optimized_N for scalar numeric PVs, with N twice the plot's width in device pixels, at most 4000; other PVs are fetched raw. See Architecture.

What the client copes with

The appliance's JSON has some quirks, all handled:

  • NaN, Infinity and -Infinity appear as bare tokens, which is not valid JSON; they are read as gaps.
  • A range with no data returns [ ], with no metadata.
  • Metadata values such as PREC may be strings ("3") or numbers.
  • The first sample may be earlier than from: it is the value in force at from, and is drawn held from the left edge.
  • optimized bins carry [mean, std, min, max, count] as the value, timestamped at the bin's centre.
  • Severity 3 with a cnxlostepsecs field marks a lost connection, drawn as a gap.

Errors

responseshown as
404 from getData.jsonthe PV is not archived: it plots live only, and its chip says "live only"
any other non-2xxthe status and the first line of the reply, on the chip and in the status line
no connectionthe transport error, likewise; live values carry on

The archiver pill turns amber for errors that are the archiver's, once a getVersion request confirms them: no connection, HTTP 502, 503 or 504, or a URL that is not an archiver (404 for data and search alike). A 404 for one PV, a 400 for an odd name, or a 500 for a bad search pattern leave it as it was. A server that answers getVersion with another HTTP error (a proxy refusing it with 401 or 403, say) counts as reachable when it answers a search.

Mock archiver

archiveview-mockarchiver is a small stand-in for an EPICS Archiver Appliance. It serves synthetic, deterministic history for a fixed set of PVs over the same HTTP API and JSON as the real appliance, quirks included. It is used by the tests, by CI's snapshots, and by the quick start.

archiveview-mockarchiver                   # http://127.0.0.1:17668
archiveview-mockarchiver --port 18000 --bind 0.0.0.0

Point archiveview at it with --archiver http://127.0.0.1:17668.

PVs

History starts 30 days before the mock starts; there is no data before that. Values are computed from the time, so the same request always gets the same answer.

MOCK:RAMP0.1 Hz sawtooth, 0 to 100
MOCK:NOISE10 Hz noise
MOCK:SLOWone sample every 5 minutes, so optimized requests come back raw
MOCK:ENUMenum index, 0 to 3
MOCK:STRINGtext
MOCK:WAVEan 8-element waveform
MOCK:NANa sine with NaN every 50th sample and periodic disconnections
bl01t:A, bl01t:B, bl01t:SUM, BL01T-MO-SIMC-01:M1.RBV, BL01T-MO-SIMC-01:M2.RBVthe names bobview-testioc serves live, so history and live values join up

Endpoints

Every endpoint is on the one port.

endpointnotes
/retrieval/data/getData.jsonpv, from, to. Operators: raw (with the last sample before from), optimized_N, mean_N, nth_N, ncount, and the …Sample_N variants that leave empty bins out
/retrieval/bpl/getMatchingPVspv (glob) or regex, limit
/retrieval/bpl/getMetadatapv
/retrieval/bpl/getVersionnone; {"version": "Archiver Appliance Version mock-…"}

As the real appliance does, it answers 404 with an HTML page for an unknown PV, 400 for an unparseable time or to before from, writes NaN as a bare token, and marks disconnections with severity 3 and cnxlostepsecs.
