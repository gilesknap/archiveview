pub fn pv_names(text: &str) -> Vec<String>
Expand description

The PV names in text, in order and once each. It is split into words on whitespace, commas and semicolons, except inside the (arguments) of a loc:// or sim:// name closed on the same line (sim://sine(0, 10, 0.1) is one word), and quotes and brackets around a word are dropped, as is a lone bracket left by a list in brackets ((A:B, C:D)).

The schemes taken are those the host’s [pv::PvManager] serves, as [pv::PvName::parse] reads them: ca:// and pva:// (in either case), and loc:// and sim://, which no archiver has, so they are plotted live only. Formulas (=expr, eq://expr) are not: their text has spaces and operators, and cannot be told from prose. Any other scheme (https://, sys://) is not a PV.

After ca:// or pva://, or with no scheme, a word can be a name if it has only characters EPICS record names use (letters, digits, _ - + : [ ] < > { } $, and . before a field), at least one letter, and does not start with - or + (a command-line flag) or start or end with . or :. After loc:// such a name can be followed by a <VType> and then (arguments), which end it (loc://x<VLong>(7)); after sim:// it is one of bobview-pv’s functions (sine, sawtooth, ramp, noise, gaussianNoise, flipflop, const), then optionally (arguments) (sim://ramp, sim://sine(0, 10, 0.1)). Unless it has a scheme, shapes that are something else are left out: times and dates (12:30:00, 2026-10-17T13:41:52Z), host:port (two parts, a host name with a ., localhost or lower case, then digits: not SR:BPM:01 or DLS:01), a::b paths, and in running text Python log lines (INFO:root:Connected; WARN:LIMIT is a name).

A selection of one word is a name if it can be one, so names with no structure at all (TEMP1, BEAMCURRENT) work. In several words only those with a scheme or some structure are kept (a :, -, _, braces, a digit or a .FIELD), so prose, shell commands and code selected with them add nothing.
